**Oriol Vinyals, Samy Bengio, Manjunath Kudlur · 2016 · [arXiv:1511.06391](https://arxiv.org/abs/1511.06391)**

By 2015 seq2seq was the default tool for variable-sized input and output. It works by breaking a joint probability into a chain — the first token, then the second given the first, and so on — which quietly requires that there *be* a first and a second.

**Many problems have no such order.** Sorting consumes a set of numbers, and a set has no first element. Modelling the joint distribution over a graphical model's variables has no canonical variable order either. In practice people used whatever order the data happened to arrive in and treated the choice as neutral. It is not neutral, and this paper measures the price.

**The measurements come first, and they are the most quotable part.** On Penn Treebank language modelling, natural and reversed word order both land at 86 perplexity — the recurrent net genuinely does not care which direction it runs. But reversing within 3-word windows costs 10 points, to 96. On constituency parsing, flattening the target tree depth-first gives 89.5 F1; flattening the same trees breadth-first, with the same model, gives 81.5. **Same information, different serialisation, eight points of F1.**

The fix for input sets is an architecture the paper calls read-process-write. The **read** block pushes each element $x_i$ through the same small network into a memory vector $m_i$. There is no recurrence here, so position never enters in the first place. The **process** block is an LSTM run for $T$ steps with no inputs and no outputs of its own, $q_t = \operatorname{LSTM}(q^\ast_{t-1})$ — it is thinking, not reading. At each step it scores every memory against its current query, $e_{i,t} = f(m_i, q_t)$, softmaxes those into weights $a_{i,t}$, reads back the weighted average $r_t = \sum_i a_{i,t} m_i$, and carries $q^\ast_t = [q_t, r_t]$ forward.

Now notice why this is order-blind. The read is a **sum** over the whole set, and addition does not care what order you add things in. Permute the inputs and you permute the summands, and the total is identical. That one observation is what Deep Sets and the Transformer encoder also rest on. The **write** block is the pointer network of the previous section, conditioned on the final query.

For output sets the paper adds a loss that maximises over orderings rather than fixing one, $\max_\pi \log p(Y_\pi(X) \mid X)$: pretrain 1000 steps treating all permutations as equally good, then pick an ordering by sampling in proportion to how likely the model finds it — which costs one evaluation rather than checking all $n!$ of them.

Sorting shows the effect. With one glimpse in the writer, ten numbers go from 28% exact-sequence accuracy for the pointer-network baseline to 57% with five processing steps. The encoder is what lasted: it became a standard order-blind readout for graph neural networks under the name set2set, used directly by [the message-passing framework](/foundation/book/sutskevers-list?section=sec-4-6).

> Serialising a set is a modelling choice with a measurable cost, and a sum over attention weights is the cheapest way to avoid making it.

**What did not survive:** the architecture softened the problem rather than solving it. Sorting fifteen numbers peaks at 10% accuracy across every configuration tried — order-blindness does not buy you an algorithm. The invariance only pays once the process block actually iterates: at zero processing steps read-process-write is no better than the plain pointer network, and at $N = 5$ it is clearly worse, 65% against 81% without glimpses and 84% against 90% with. The output-order loss is weaker than it sounds, too. Sampling one permutation in proportion to its own likelihood reinforces whatever order the model already leans toward, and the paper offers no guarantee that this order is a good one.
