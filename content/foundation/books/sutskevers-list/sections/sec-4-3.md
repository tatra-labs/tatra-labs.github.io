**Oriol Vinyals, Samy Bengio, Manjunath Kudlur · 2016 · [arXiv:1511.06391](https://arxiv.org/abs/1511.06391)**

By 2015 seq2seq was the default tool for variable-sized input and output. It factors a joint distribution with the chain rule, one token at a time, left to right, and that factorisation requires a left and a right. Many problems have neither. Sorting consumes a set of numbers, and the input has no first element. Modelling the joint distribution of a graphical model's variables has no canonical variable order. In practice people used whatever order the data arrived in and treated the choice as neutral. It is not neutral, and this paper measures the price.

The measurements come first. On Penn Treebank language modelling, natural and reversed word order both land at 86 perplexity — the recurrent net does not care which direction it runs — but reversing within 3-word windows costs 10 points, to 96. On constituency parsing, linearising the target tree depth-first gives 89.5 F1; breadth-first, same trees and same model, gives 81.5. Same information, different serialisation, eight points of F1.

The fix for input sets is an architecture the paper calls read-process-write. The read block embeds each element `x_i` through the same small network into a memory vector `m_i`. There is no recurrence, so position never enters. The process block is an LSTM run for `T` steps with no inputs and no outputs of its own, `q_t = LSTM(q*_{t−1})`. At each step it scores every memory against the query, `e_{i,t} = f(m_i, q_t)`, normalises with a softmax to `a_{i,t}`, reads back `r_t = Σ_i a_{i,t} m_i`, and carries `q*_t = [q_t, r_t]`. Because the read is a sum over the whole set, permuting the inputs permutes the summands and leaves `q*_T` unchanged. That sum is where the invariance comes from, and it is the observation Deep Sets and the Transformer encoder also rest on. The write block is the pointer network of 4.2, conditioned on `q*_T`. For output sets the paper adds a loss that maximises over orderings instead of fixing one, `max_π log p(Y_π(X)|X)`: pretrain 1000 steps under a uniform prior over permutations, then pick an ordering by sampling in proportion to `p(Y_π(X)|X)`, which needs one evaluation of `p(·)` rather than `n!`.

Sorting shows the effect. With one glimpse in the writer, ten numbers go from 28% exact-sequence accuracy for the pointer-network baseline to 57% with five processing steps. The encoder is what lasted: it became a standard permutation-invariant readout for graph neural networks under the name set2set, which 4.6 uses directly.

> Serialising a set is a modelling choice with a measurable cost, and a sum over attention weights is the cheapest way to avoid making it.

**What did not survive:** the architecture softened the problem rather than solving it. Sorting fifteen numbers peaks at 10% accuracy across every configuration tried. The invariance only pays once the process block iterates: at zero processing steps read-process-write is no better than the plain pointer network, and at `N = 5` it is clearly worse — 65% against 81% without glimpses, 84% against 90% with. The output-order loss is weaker than it sounds too. Sampling one permutation in proportion to its own likelihood reinforces whatever order the model already prefers, and the paper offers no guarantee that order is a good one.
