**A. Shen, V. A. Uspensky, N. Vereshchagin · 2017 · [AMS Surveys 220](https://bookstore.ams.org/surv-220)**

Both previous entries measure a model by how long its description is, and both leave that length hanging on a code somebody picked in advance. This is a real hole. Any string you like can be given a one-bit codeword by a code built around it, so "short description" means nothing until you say short in what language.

Shannon entropy does not plug the hole, and the reason is worth being precise about. Entropy is a property of a *distribution* — a process that emits symbols with certain probabilities — not a property of any particular object that comes out. So entropy has nothing at all to say about whether `0101010101` is more regular than a coin-flip string of the same length. Both are equally likely from a fair coin. Yet one of them obviously has a pattern. Until the mid-1960s there was no definition of the complexity of a single finite object. Solomonoff, Kolmogorov and Chaitin arrived at one independently, and this textbook is the standard account of what followed.

**The definition is short.** Fix a universal machine $U$ — any general-purpose computer will do. Then $C(x)$, the complexity of the string $x$, is the length of the shortest program $p$ such that running it gives you $x$. A repetitive string has a short program. A random one has none shorter than just printing it out literally.

The choice of machine looks fatal, since a different computer would give different lengths. The **invariance theorem** rescues it: for any other description method $V$ there is a constant $c$ with $C_U(x) \leq C_V(x) + c$ for every $x$. That constant is simply the length of an interpreter for $V$ written in $U$'s language — write the translator once and it serves for all data forever. So it depends on the two languages and not on what you are measuring, and complexity is well defined up to an additive constant.

A counting argument does the rest, and it is the kind you can check on your fingers. There are fewer than $2^n$ possible programs shorter than $n$ bits, but there are $2^n$ strings of length $n$, so most strings of length $n$ cannot have a program much shorter than themselves: $C(x) \geq n - O(1)$. **Incompressibility is not the exception, it is the overwhelming rule.** The compressible objects are a vanishing minority — which happens to include almost everything anyone cares about.

$C$ is not computable. It is only *upper* semicomputable: you can run every program in parallel and lower your estimate each time a short one halts having produced $x$, but you never learn when to stop waiting. The proof that you cannot do better is Berry's paradox made rigorous — "the smallest number not describable in under twelve words" is a description of it in eleven — since a program of roughly $\log n$ bits could otherwise search for the first string with $C(x) > n$ and print it, describing in $\log n$ bits something that by definition needs more than $n$.

From there the book builds algorithmic randomness. Martin-Löf calls an infinite sequence random if it passes every statistical test you could actually write down. The Levin-Schnorr theorem shows this holds exactly when the complexity of the sequence's first $n$ symbols stays within a constant of $n$ for every $n$ — random means incompressible, all the way down, and the two definitions turn out to describe the same sequences. Plain $C$ cannot even state that condition, because it dips below $n$ infinitely often for every sequence, which is why the middle chapters switch to prefix-free codes, where no codeword is the start of another, and to the a priori probability $m$, with $K(x) = -\log m(x) + O(1)$.

The chapter on algorithmic statistics then rebuilds the previous section's two-part code with no chosen encoding at all: name a finite set that contains $x$, then give the index of $x$ within it. MDL is that same split, with the model class restricted to something a computer can actually handle.

The book earns its place by supplying the ceiling. Every practical compressor, `gzip` or a transformer, is an attempt on a quantity proved here to be out of reach. 511 pages, exercises throughout, translated from the authors' Russian textbook.

> Compression has a well-defined optimum, and it is uncomputable.

**The caveat:** the $O(1)$ is load-bearing and unbounded. Invariance only promises that the gap stops mattering as strings get long; an adversarial choice of machine inflates the constant as much as you like, so $K(x)$ for a fixed finite string is not a number anyone can pin down. Nothing here yields an algorithm, and there is no bound on the gap between what a trained model achieves and $C(x)$. The book also contains no machine learning whatsoever — no networks, no generalisation bounds. The connection to the rest of this list is one the reader supplies.
