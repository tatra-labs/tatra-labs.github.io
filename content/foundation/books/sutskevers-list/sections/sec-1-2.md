**Peter Grünwald · 2004 · [arXiv:math/0406077](https://arxiv.org/abs/math/0406077)**

The previous entry priced one network's weights in bits. Pricing a model class was messier. "Prefer the simpler model" had several incompatible formalisations: AIC penalises the log-likelihood by `k`, BIC by `(k/2) log n`, structural risk minimisation by a capacity term, cross-validation by nothing at all — each from a different asymptotic argument, each disagreeing on real data. The clean answer, the shortest program that outputs the data, is uncomputable — the next section is why. Grünwald's 80-page tutorial, an extended version of the first two chapters of the MIT Press volume *Advances in Minimum Description Length*, sits in that gap.

The first move is the two-part code, which Grünwald calls crude MDL: pick the hypothesis `H` minimising `L(H) + L(D|H)`, bits for the hypothesis plus bits for the data given the hypothesis. For polynomial regression, `L(H)` pays for the coefficients and `L(D|H)` for the residuals under a Gaussian noise model. Raising the degree shortens the second term and lengthens the first, so the sum has an interior minimum and overfitting shows up as a code that got longer. The tutorial is blunt that this is unfinished: `L(H)` is a free choice of encoding, and any hypothesis can be made to win by giving it a short codeword.

Refined MDL removes that freedom by refusing to split the code. A whole parametric family `M` gets one code, chosen so its worst-case excess length over the best-fitting member is as small as possible. That code is Shtarkov's normalized maximum likelihood, `P_nml(x) = P(x | θ̂(x)) / Σ_y P(y | θ̂(y))`, where `θ̂(x)` is the ML fit to `x` and the sum runs over every dataset of that length. Its codelength is `-log P(x | θ̂(x)) + COMP(M)`, where the parametric complexity `COMP(M)` is the log of that normalising sum. The regret, the gap to the best-fitting member, is then identical for every sequence, which is what makes it minimax. A family flexible enough to fit many datasets well pays for it here. Under regularity conditions, `COMP(M) = (k/2) log(n/2π) + log ∫ sqrt(det I(θ)) dθ + o(1)`: parameter counting falls out as a consequence rather than being assumed, and two families with the same `k` but different reach are separated by the Fisher-information term. For exponential families this becomes indistinguishable from Bayes factor selection under Jeffreys' prior: the same arithmetic, justified by a coding guarantee instead of by a prior encoding belief.

The result is a common unit. Fit, model complexity and the penalty for choosing among candidates are all measured in bits, so the trade that the neighbouring entries assume can be computed rather than argued.

> Model complexity is not the number of parameters but the log of how much likelihood the family can spread across all the datasets it might have seen.

**The caveat:** the NML normalising sum diverges for many ordinary families. For the Gaussian location model with unconstrained mean it is infinite, as is Jeffreys' prior over the same space. The central object of refined MDL often does not exist until the parameter range is truncated, and choosing that truncation reintroduces the arbitrariness the two-part code was dropped to escape. The `(k/2) log n` intuition also transfers badly to overparameterised networks, where adding parameters can reduce test error.
