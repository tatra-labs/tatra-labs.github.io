**Peter Grünwald · 2004 · [arXiv:math/0406077](https://arxiv.org/abs/math/0406077)**

The previous entry priced one network's weights in bits. Pricing a whole *kind* of model was messier. Everyone agreed you should "prefer the simpler model"; nobody agreed what that meant. Several rival formulas existed, each charging a different penalty for complexity and each derived from a different argument: AIC docks you $k$, the number of parameters; BIC docks you $(k/2) \log n$, where $n$ is how many data points you have; structural risk minimisation docks you a capacity term; cross-validation docks you nothing and just tries the model on held-out data. On real problems they disagree with each other. The clean answer — the shortest computer program that outputs your data — is uncomputable, and the next section is why. Grünwald's 80-page tutorial, an extended version of the first two chapters of the MIT Press volume *Advances in Minimum Description Length*, lives in that gap.

**The first move is the two-part code**, which Grünwald himself calls crude MDL. Pick the hypothesis $H$ that minimises $L(H) + L(D \mid H)$: the bits needed to write down the hypothesis, plus the bits needed to write down the data once you have that hypothesis in hand. Fitting a curve to points makes this concrete. $L(H)$ pays to state the coefficients of the polynomial. $L(D \mid H)$ pays to state how far each point sits off the curve. Raise the degree of the polynomial and the second term shrinks, because the curve passes closer to the points — but the first term grows, because there are more coefficients to state. The sum therefore has a genuine minimum somewhere in the middle, and this is the appealing part: **overfitting stops being a judgement call and becomes a measurement.** The overfitted model is the one whose total description got longer.

The tutorial is blunt that this is unfinished. $L(H)$ depends on a coding scheme you chose, and any hypothesis at all can be made to win by handing it a short codeword.

**Refined MDL removes that freedom by refusing to split the code in two.** An entire family of models $M$ — say, all polynomials of degree three — gets one single code, chosen so that its worst case is as good as possible. Specifically, you compare it against the best-fitting member of the family, chosen with hindsight after seeing the data, and you pick the code whose largest possible shortfall against that hindsight choice is as small as it can be. The code that achieves this is Shtarkov's normalized maximum likelihood, $P_{\text{nml}}(x) = \frac{P(x \mid \hat\theta(x))}{\sum_y P(y \mid \hat\theta(y))}$, where $\hat\theta(x)$ is the best-fitting setting of the parameters for the data $x$ you actually saw, and the sum on the bottom runs over every dataset of that length you *might* have seen.

Its length works out to $-\log P(x \mid \hat\theta(x)) + \operatorname{COMP}(M)$: how badly the best member of the family fits your data, plus a fixed charge called the parametric complexity, which is the log of that normalising sum. Because that charge is the same no matter which dataset arrives, the shortfall against hindsight is identical for every sequence — which is exactly what makes the code minimax, best in the worst case.

Now look at what the charge is made of. The sum on the bottom is large when the family can fit many different datasets well. **So a family flexible enough to explain anything pays for that flexibility here, in bits, automatically.** Under mild conditions it comes out as $\operatorname{COMP}(M) = (k/2) \log(n/2\pi) + \log \int \sqrt{\det I(\theta)} \thinspace d\theta + o(1)$. Notice the first term: counting parameters falls out as a *consequence* rather than being assumed at the start, which is what the older formulas could never explain. And the second term separates two families with the same number of parameters but different reach. For a common class of models this becomes arithmetically indistinguishable from standard Bayesian model selection — the same sums, justified by a guarantee about codelength instead of by a prior encoding somebody's belief.

The payoff is a common unit. Goodness of fit, model complexity, and the penalty for having shopped among candidates are all measured in bits, so the trade-off the neighbouring entries take for granted can be computed rather than argued about.

> Model complexity is not the number of parameters but the log of how much likelihood the family can spread across all the datasets it might have seen.

**The caveat:** that normalising sum diverges for many perfectly ordinary families. For a Gaussian whose mean is unconstrained it is infinite, as is the matching Bayesian prior. The central object of refined MDL frequently does not exist until you cut the parameter range down to something finite, and choosing where to cut smuggles back in the arbitrariness the two-part code was abandoned to escape. The $(k/2) \log n$ intuition also transfers badly to modern overparameterised networks, where adding parameters can *reduce* test error rather than increase it.
