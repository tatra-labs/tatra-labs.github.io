**Alex Graves, Greg Wayne, Ivo Danihelka · 2014 · [arXiv:1410.5401](https://arxiv.org/abs/1410.5401)**

An LSTM keeps everything it knows in one fixed-width hidden state. So a network asked to hold a sequence word for word has to smear it across the same vector it uses for everything else, and there is no slot to put it in.

The copy task shows this cleanly. Present a series of eight-bit random vectors, then a delimiter, then ask for them back. An LSTM trained on lengths randomised between 1 and 20 degrades rapidly past 20 — **it fitted a function, not a procedure.** A person given this task writes the items down and reads them back, and the writing-down is the missing piece: addressable working memory, where the item stored at position $i$ is kept separate from the procedure operating on it.

The NTM couples a controller to an external memory matrix $M_t$ — 128 locations of 20 values each, in every reported experiment. The controller, feedforward or LSTM, emits the parameters of one memory access per head. Reading is a weighted average over rows, $r_t = \sum_i w_t(i) M_t(i)$, where $w_t$ is a set of weights summing to one across the 128 rows. Writing splits into erase then add, borrowed directly from the LSTM's forget and input gates: $\tilde M_t(i) = M_{t-1}(i)[1 - w_t(i)e_t]$, then $M_t(i) = \tilde M_t(i) + w_t(i)a_t$.

**Nothing here indexes.** There is no "go to row 57". Every access touches all 128 rows in proportion to the weights, and that is precisely what makes the whole thing differentiable, so gradient descent can learn where to put things. A hard lookup has no gradient; a weighted average does. That soft read over a bank of vectors recurs throughout this chapter.

The weighting is assembled in stages, and the two stages answer two different questions. **Content addressing** asks *where is the thing that looks like this*: the head emits a key $k_t$, compares it against every row by cosine similarity, and softmaxes the result, sharpened by a strength $\beta_t$. **Location addressing** asks *where is the row next to the one I used last*: an interpolation gate blends the content result against the head's previous weighting, $w_t^g = g_t w_t^c + (1 - g_t) w_{t-1}$; a distribution $s_t$ over integer offsets then rotates it by a shift that wraps around the end; and a sharpening exponent $\gamma_t \geq 1$ reconcentrates whatever that shift blurred.

The copy solution combines both, and it is a genuine algorithm: content-address the start of the buffer, then advance one location per step. Because the advance is *relative*, it does not care how long the sequence is.

Trained on lengths 1 to 20, the NTM copies test sequences of 30 and 50 with no retraining. At 120 one vector is duplicated and pushes everything after it a step back, which the paper calls subjectively close to a correct copy. On associative recall — three six-bit vectors per item, 2 to 6 items per episode — it reaches near-zero cost in about 30,000 episodes, where an LSTM does not get there in a million. The feedforward copy model has 17,162 parameters against 1,352,969 for the LSTM baseline. It earns its place for showing that content matching works as a memory interface rather than merely an alignment trick, and that a learned algorithm can outrun the range it was trained on.

> Make memory addressing differentiable and a network can learn where to put things, not only what to compute.

**What did not survive:** the hand-built location machinery. The interpolation gate, the circular shift and the sharpening exponent were all bolted on to make iteration possible, and each is a guess about how memory should be traversed. The DNC replaced them two years later with a learned link between locations and usage-based allocation; Transformers kept content addressing and dropped the write head entirely. The strain shows in the paper itself: repeat copy was trained with length and repeat count both drawn from 1 to 10, and past that range the network keeps duplicating correctly but "is unable to keep count of how many repeats it has completed, and does not predict the end marker correctly".
