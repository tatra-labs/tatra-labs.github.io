**Lilian Weng · 2020 · [Lil'Log](https://lilianweng.github.io/posts/2020-01-29-curriculum-rl/)**

[Exploration](/foundation/book/wengs-guide?section=sec-1-4) attacks the problem of rare rewards by making the agent smarter about where it looks. Curriculum learning attacks the same problem from the other side: change *what the agent is asked to do*, so that the reward stops being rare in the first place. Start with problems it can nearly solve, and advance only as it does.

The organising idea is the **zone of proximal development** — the band of tasks that are neither trivially easy nor impossibly hard. The argument for it is sharper than it first looks. A task the agent always solves produces no learning signal, because there is nothing to correct. A task it *never* solves produces no signal either, because there is no successful attempt to reinforce. **Both extremes teach exactly nothing.** Everything useful happens in between, and the practical form of that is a target success-rate band: keep tasks the agent currently solves somewhere between rarely and usually.

The families the post surveys differ in *who chooses* the next task. **Hand-designed curricula** work and do not scale, because somebody has to know the difficulty ordering in advance. **Teacher-guided curricula** make the choice itself a learning problem — a teacher picks tasks to maximise how fast the student is improving, which turns the curriculum into a bandit problem over tasks and connects the whole business back to [1.3](/foundation/book/wengs-guide?section=sec-1-3). **Self-play** generates its own curriculum for free, because the opponent improves at exactly the rate you do — which is why it worked so well for board games and so poorly for anything without a symmetric adversary. **Automatic goal generation** trains a generator to propose goals whose current success probability sits in the intermediate band, so the frontier of competence advances on its own.

> A task that is always solved and a task that is never solved carry the same amount of information, which is none; learning happens only in the band between them.

**This is the post that transferred most directly, and almost nobody credits it.** Reinforcement learning with verifiable rewards — the regime behind current reasoning models — depends on difficulty filtering to function at all, and the reason is mechanical rather than pedagogical.

GRPO works out how good each response was by comparing it against the average of the group sampled from the same prompt. Now consider the two extremes. If all `k` attempts succeed, every reward equals the average, so every comparison is zero, and **the gradient is exactly zero.** If all `k` fail, precisely the same thing happens. A prompt contributes to learning only when the model's pass rate is strictly between zero and one — which is the zone of proximal development arriving as an algebraic identity rather than as an educational metaphor.

So practitioners filter training prompts by measured pass rate, discard the saturated and the impossible, and re-measure as the model improves — a teacher-guided curriculum in which the teacher is a rollout counter. That is the crudest method in the post, and it is the one that works.

**What did not survive:** the sophisticated half. Learned goal generators, adversarial goal proposal and explicit learning-progress signals mostly stayed in the papers, for a consistent reason: those signals are noisy, they require the difficulty measure to be cheap, and measured pass rate is both cheap and unbiased.

There is also a second-order problem the post does not anticipate and current practice has run into — **the curriculum shapes the policy in ways nobody chose.** Filtering to intermediate-difficulty problems means training disproportionately on one particular slice of the distribution, and a model trained only on what it nearly knows can sharpen there while quietly losing ground elsewhere. Difficulty filtering is a curriculum whether or not anyone designed it as one, and its effect on the final model is not routinely measured.
