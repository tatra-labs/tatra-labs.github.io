**Lilian Weng · 2020 · [Lil'Log](https://lilianweng.github.io/posts/2020-06-07-exploration-drl/)**

Bandit exploration works because you can pull every arm often enough to bound your uncertainty about it. Scale to a deep reinforcement learning problem with sparse reward and that stops being possible. Montezuma's Revenge is the standing example: the agent must climb down a ladder, cross a room, collect a key and open a door before receiving any reward at all, and a randomly exploring agent will not do that sequence in the lifetime of the universe. Epsilon-greedy is not a weak solution here; it is not a solution.

The post organises the responses into families, and the useful distinction is **what each one treats as evidence of novelty.**

**Count-based methods** want to visit rarely-visited states, which requires counting states, which is meaningless in a continuous or high-dimensional space where nothing is ever visited twice. Pseudo-counts recover a usable count from a density model — if a state's estimated probability rises after seeing it, the size of that rise implies how often something like it has been seen. Hash-based approaches discretise the state and count buckets.

**Prediction-error methods** treat "hard to predict" as a proxy for "unfamiliar". The Intrinsic Curiosity Module trains a forward model and rewards the agent where the model is wrong, with an important refinement: the prediction happens in a feature space learned through an *inverse* dynamics model, which is trained to recover the action from a pair of consecutive states and therefore learns to represent only what the agent can control. **Random Network Distillation** is the cleanest idea in the post — freeze a randomly initialised network, train a second network to predict its output on visited states, and use the prediction error as the bonus. Error is high where the predictor has not been trained, which is exactly where the agent has not been.

RND's design also solves the failure that makes naive curiosity useless. **The noisy-TV problem:** put a screen of random static in the environment and a prediction-error agent will sit in front of it forever, because the static is genuinely unpredictable and therefore permanently "novel". RND is immune because its target is a deterministic function of the state — a random network, but a *fixed* one — so a stochastic environment produces no irreducible error.

**Memory-based methods** stop approximating and store things. Episodic memory gives a novelty bonus by comparing the current state against everything recently seen; Go-Explore keeps an archive of promising states and *returns to them directly* before exploring further, rather than hoping a stochastic policy rediscovers a hundred-step prefix.

> Curiosity works only if novelty is measured in a space where the agent's own actions are the source of the surprise; otherwise the agent finds a source of noise and stares at it.

**What did not transfer, which is most of it, and the reason is worth understanding.** Almost none of this machinery appears in reinforcement learning for language models, and it is not for lack of trying. Novelty bonuses require a notion of state visitation, and **novel text is free**. A language model can emit an unbounded quantity of strings no model has ever produced, all of them worthless; prediction-error novelty in token space rewards incoherence, which is the noisy-TV problem in its purest form, with the model as its own television.

So practice fell back to the crudest tools available: sample at temperature, draw many rollouts per prompt, and hold the policy near its initialisation with a KL penalty. That is epsilon-greedy with a leash. The consequences are visible in current training runs — entropy collapses, the policy sharpens onto whatever it found first, and `pass@1` improves while `pass@k` degrades, which is precisely a system that has stopped exploring. Weng returns to this from the other end in [Harness Engineering](/foundation/book/wengs-guide?section=sec-5-3), where diversity collapse in evolutionary search appears on her list of unsolved bottlenecks. This post is the best available account of how the problem was attacked when the state space was an Atari screen, and reading it mostly establishes how little of that we can currently use.
