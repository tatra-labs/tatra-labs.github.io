**Lilian Weng · 2023 · [Lil'Log](https://lilianweng.github.io/posts/2023-06-23-agent/)**

The most-cited post on Lil'Log, and the one that supplied the vocabulary. When people say an agent has planning, memory and tools, they are using this decomposition, usually without knowing where it came from. The post's structure is its contribution: **an LLM-powered agent is a model surrounded by three subsystems**, and almost every agent framework since is an implementation of that diagram.

**Planning** splits into decomposition and reflection. Decomposition breaks a goal into steps — [chain-of-thought](/foundation/book/karpathys-list?section=sec-5-2), [tree of thoughts](/foundation/book/karpathys-list?section=sec-5-3), or handing the problem to a classical planner and translating back. Reflection is the loop that makes the agent recoverable rather than merely sequential: ReAct interleaves reasoning traces with actions so that an observation can change the plan, and Reflexion adds a verbal self-critique after failure that is carried into the next attempt as context. **The important property is that this is learning without gradients** — the improvement is written into the context window, which is [RL^2](/foundation/book/wengs-guide?section=sec-2-2) again, with English as the hidden state.

**Memory** is mapped onto a human analogy — sensory, short-term, long-term — where short-term is the context window and long-term is an external store queried by approximate nearest neighbour search. The post's coverage of the ANN algorithms themselves (LSH, HNSW, FAISS, ScaNN) is the practical part, and the honest observation is that "long-term memory" here means a vector index, with all the retrieval failures that implies.

**Tool use** covers the mechanisms from [Toolformer](/foundation/book/karpathys-list?section=sec-6-2) onward, and the case studies are where the post shows its age most vividly: ChemCrow, HuggingGPT, AutoGPT, GPT-Engineer, and the Generative Agents simulation whose memory stream — scored by recency, importance and relevance, with periodic reflection synthesising higher-level observations — remains the most interesting memory design in the post.

> An agent is a model plus a plan it can revise, a place to write things down, and something it can do; the interesting engineering is entirely in the second and third.

**What did not survive: the frameworks, comprehensively.** AutoGPT became the standard cautionary example — an agent that loops with great apparent purpose, spends money, and completes nothing, because it had no mechanism for recognising it was stuck. HuggingGPT-style model-routing schemes were absorbed into general tool calling. The lesson the field drew, correctly, was that **reliability comes from training the model on agentic trajectories, not from wrapping a non-agentic model in more orchestration.** Scaffolding was widely reinterpreted as a crutch.

**Then the pendulum came back**, which is what makes reading this post alongside [Harness Engineering](/foundation/book/wengs-guide?section=sec-5-3) worthwhile. The 2026 position is that the scaffolding matters a great deal after all — but as *code that gets optimised and evaluated*, not as a hand-tuned prompt chain. The same three subsystems appear there under different names: workflow loops for planning, the file system for memory, sub-agents for delegation.

The most impressive thing about the post is its final section. The challenges it names in 2023 — **finite context length, unreliable long-horizon planning and decomposition, and the unreliability of a natural-language interface between components** — are, essentially unchanged, the three things still limiting agents in 2026. Context windows grew by two orders of magnitude and the constraint did not go away; it turned into a question about what to keep. That is an unusually good prediction record for a survey written at the very beginning of a hype cycle.
