# 10.8 Echo State Networks

If the recurrent weights are the hard part to learn, one response is not to learn them. Echo state
networks set the recurrent and input weights by hand and train only the output layer.

## The idea

The recurrent hidden units form a **reservoir** — a fixed, randomly initialised dynamical system that
transforms the input sequence into a rich set of temporal features. Only the mapping from reservoir state
to output is trained, and because that map is linear, training is a convex problem with a closed-form
solution.

The name for the family is **reservoir computing**; liquid state machines are the spiking-neuron version.

## Setting the weights

The reservoir cannot be initialised arbitrarily. The book frames the criterion in terms of the **spectral
radius** of the recurrent weight matrix — the magnitude of its largest eigenvalue. This is Section 10.7's
analysis used as a design rule rather than as a diagnosis of failure.

A spectral radius well below one makes information decay quickly, so the reservoir forgets. Above one, the
dynamics explode. The recommendation is to set it slightly **greater than** one, relying on the saturating
nonlinearities to prevent actual divergence: the linear analysis says the state grows, and the squashing
function bounds it, leaving a system that is sensitive to its input history without being unstable.

The book notes that this is a strategy for setting weights rather than a complete answer, and mentions the
possibility of using echo-state initialisation as a starting point for full training.

## My take

The interesting claim here is the one that connects back to 9.9. Random convolutional filters already
implement useful frequency-selective detectors; a random recurrent reservoir already implements a useful
temporal basis. In both cases the architecture is doing more of the work than the learning is, and it is
worth knowing which problems have that property.

Echo state networks were genuinely competitive on small time-series problems and never scaled. The reason
is not mysterious: a fixed random reservoir has to be large to be expressive, since it cannot specialise
to the task, and the trained linear readout can only combine what the reservoir happens to provide. Every
increment of capability costs reservoir size rather than parameters, and that trade is bad as soon as
training the recurrent weights becomes feasible — which is what LSTM and gradient clipping made possible.

The spectral-radius criterion is the part worth keeping, and it generalises. "Set the recurrent dynamics
near the edge of stability" is the same instruction as orthogonal initialisation for RNNs, as the unit
spectral norm targeted by spectral normalisation in GANs, and as the residual-stream scaling rules used in
deep transformers. The underlying idea — that a deep or long-running computation should neither amplify
nor attenuate on average — has outlived every architecture in this chapter.
