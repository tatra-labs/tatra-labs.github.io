# 14.2 Regularized Autoencoders

If limiting the code size is one way to prevent an autoencoder from learning the identity, regularisation
is the other — and the more useful one, because it allows the code to be as large as needed.

## The idea

An **overcomplete** autoencoder, with a code at least as large as the input, can trivially copy. A
regularised autoencoder uses a loss that encourages properties other than copying, so that even a
high-capacity model with a large code learns something. The book lists the properties typically wanted:
sparsity of the representation, small derivatives of the representation with respect to the input, and
robustness to noise or to missing inputs.

The framing the authors emphasise is that a regularised autoencoder can be nonlinear and overcomplete and
still learn something useful about the data distribution, and that this does not depend on keeping the
model small.

## Sparse autoencoders

The training criterion adds a sparsity penalty on the code:

$$
L\left( x, g(f(x)) \right) + \Omega(h)
$$

The book gives an interpretation of this that is worth following, because it explains where the penalty
comes from. A sparse autoencoder can be understood as approximating maximum likelihood in a **generative
model with latent variables**: the joint $p(x, h)$ factorises as $p(h) p(x \mid h)$, and if the prior
$p(h)$ is sparsity-inducing — Laplace, say — then $-\log p(h)$ is an absolute-value penalty on the code.
The sparsity term is a **log-prior**, not an arbitrary addition, which is the same argument Section 5.6
made for weight decay.

## Denoising autoencoders

A different route to the same goal: rather than adding a term to the loss, change the loss itself. A
**denoising autoencoder** minimises

$$
L\left( x, g(f(\tilde x)) \right)
$$

where $\tilde x$ is a corrupted copy of $x$. The model must now undo the corruption, which is impossible
by copying. Section 14.5 develops this.

## Penalising derivatives

The third strategy penalises the sensitivity of the code to the input, using a term based on the
derivatives of $h$ with respect to $x$. This makes the representation change slowly as the input varies,
so it is insensitive to directions in which the data does not move — the **contractive autoencoder** of
14.7.

## My take

The latent-variable reading of the sparsity penalty is the part to take seriously, because it converts
Chapter 14 from a collection of tricks into a chapter about approximate inference. An autoencoder with a
penalised code is doing something like MAP inference in a generative model, with the encoder as a fast
approximation to the posterior. Read that way, the step from here to the variational autoencoder is
short: replace the point estimate with a distribution and the penalty with a KL divergence to the prior,
and the objective becomes a proper bound on the likelihood rather than an analogy to one.

The three strategies also line up with a distinction worth keeping. Sparsity constrains **what the code
contains**; denoising constrains **what the model must be able to do**; derivative penalties constrain
**how the code responds to change**. Only the second changes the task rather than the objective, and it is
the one that scaled — masked language modelling and diffusion are both denoising objectives, and neither
sparsity nor Jacobian penalties are used at scale anywhere.
