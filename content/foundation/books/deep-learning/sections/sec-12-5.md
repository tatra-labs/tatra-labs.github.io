# 12.5 Other Applications

A survey of everything that did not fit the previous four sections. Two topics get real treatment:
recommender systems, and knowledge representation.

## Recommender systems

The commercial workhorse. The task is to predict how a user will respond to an item, which the book frames
as supervised learning over user-item pairs.

The classical approach is **collaborative filtering**: represent each user and each item by an embedding
vector, and predict the rating from their inner product plus bias terms. The rating matrix is factorised
into a user matrix and an item matrix, and the book notes this can be done by singular value decomposition
or, better, by directly minimising squared error on the observed entries with gradient descent — SVD
requires filling in the missing values, which are the majority.

The failure mode is the **cold start** problem: a new user or a new item has no interaction history, so
collaborative filtering has nothing to work with. The remedy is **content-based** information — attributes
of the item, or of the user — which allows a prediction before any interactions exist.

The section then makes a point that separates recommendation from ordinary supervised learning. A
recommender **influences the data it later observes**. Only recommended items get feedback, so the system
never learns what would have happened had it recommended something else. This is the exploration-versus-
exploitation problem, and the book connects it to **contextual bandits** and reinforcement learning: the
system must sometimes recommend suboptimally in order to learn.

## Knowledge representation and reasoning

The second half considers structured knowledge. Embeddings for words generalise to embeddings for
**entities and relations**, learned from a knowledge base of triples — subject, relation, object — or
extracted from free text. A model scores whether a triple is true, and can then propose links absent from
the knowledge base, which is **link prediction**.

The book is candid that quantitative evaluation here is difficult, since a proposed fact absent from the
base may be true rather than wrong, and mentions that these representations support question answering
and reasoning but that performance was far from what the applications require.

## My take

The feedback-loop observation is the most important idea in the section, and it is the one that has aged
into a serious problem rather than a technical curiosity. A deployed recommender does not observe a fixed
distribution; it observes the consequences of its own past behaviour, which violates the i.i.d. assumption
that Chapter 5 built everything on. Section 3.5's distinction between conditioning and intervening is the
formal version of the same point, and this is where it lands in practice.

The consequences run well past accuracy. A system optimising engagement on data generated by its own
prior recommendations will narrow what it shows, and the resulting concentration is a mathematical
property of the loop rather than a design choice anyone made. The book identifies the mechanism in a
paragraph and treats it as a bandit problem; the intervening decade established it as one of the central
questions about deployed machine learning.

The knowledge-representation half reads very differently now. The book describes explicit knowledge bases
as the way to give a system facts, with neural embeddings as a way to complete them. What happened instead
is that facts ended up **in the weights** of a language model, learned incidentally from text, with no
knowledge base anywhere — and the resulting problems, that stored facts cannot be updated or verified,
are precisely the ones an explicit knowledge base does not have. Retrieval-augmented generation is the
field walking part of the way back.

The authors' assessment that performance was far from what these applications require was accurate then
and describes a gap that narrowed enormously and did not close.
