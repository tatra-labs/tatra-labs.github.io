# 10.6 Recursive Neural Networks

A different generalisation of the recurrent idea: instead of applying the shared function along a chain,
apply it along a **tree**.

## The structure

A recursive network has a computational graph shaped as a deep tree rather than a chain-like unfolding.
The same weights are shared at every node, and the tree combines children into parents until a single
root representation remains.

The advantage the book emphasises is depth. For a sequence of length $\tau$, a recurrent network has a
path of length $\tau$ from the first input to the output; a balanced binary tree has a path of length
$O(\log \tau)$. That is a dramatic shortening of the credit-assignment path, and it directly addresses the
long-term-dependency problem of 10.7.

The open question the section identifies is **how to choose the tree structure**. One option is a
structure independent of the data, such as a balanced binary tree. Another is to use an externally
provided structure — for natural language, the parse tree produced by a syntactic parser. Another is to
have the network itself propose the structure, which the book notes is harder.

There are also variants in what happens at each node: a single shared weight matrix, or something more
elaborate such as a tensor-based composition operator.

## My take

The logarithmic path length is the right idea and the tree was the wrong vehicle. Recursive networks had a
real run in sentiment analysis and semantic composition, where a parse tree was available and appeared to
carry the relevant structure, and they disappeared almost completely.

Three reasons, and they are worth separating because only one is about accuracy. **The tree must come from
somewhere** — a parser, which is itself a model with its own errors, and which does not exist for most
data types. **Trees do not batch.** Every example has a different shape, so the efficient dense matrix
operations that make neural networks fast on parallel hardware are unavailable, and the implementations
required elaborate machinery to group nodes by depth. And empirically, the syntactic structure turned out
not to be worth its cost once sequence models got good enough.

What did survive is the objective. Shortening the path between distant elements is exactly what attention
achieves — every position reaches every other in a single layer, giving $O(1)$ path length rather than
$O(\log \tau)$ or $O(\tau)$. The transformer is the answer to the question this section is asking, arrived
at by removing the structure rather than by imposing a better one, and it batches perfectly because every
example has the same shape.

Read this section as the field's most explicit attempt to buy short paths with architecture, and as an
illustration that a structural prior which cannot be batched will lose to one that can, almost regardless
of how good it is.
