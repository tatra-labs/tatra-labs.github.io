# 16.5 Learning about Dependencies

Where does the graph come from? The section contrasts two answers, and the choice between them is one of
the defining differences between the graphical-model tradition and deep learning.

## Structure learning

The first answer is to **learn the graph** — search over structures, fit each one, and score it by
training-set fit penalised for complexity. Greedy search is the usual approach: propose an edge addition
or removal, retrain, keep the change if the score improves.

The book's objection is cost. Every structural change requires refitting the model, so the search is
expensive, and the discrete search space makes gradient methods unavailable.

## Latent variables instead

The second answer, and the one deep learning takes, is to **use latent variables rather than adaptive
structure**. Fix a simple, dense structure — every visible unit connected to every latent unit — and let
the parameters express the dependencies.

The argument the book makes is that latent variables capture dependencies among the visible variables
indirectly. Two visible variables that appear connected are connected *through* a shared latent variable,
and the strength of the connection is a continuous parameter that gradient descent can adjust. Structure
that would require a discrete search becomes a continuous optimisation.

Latent variables also have a second use: they provide a **representation** of the data, which is what
Chapter 15 was about. A latent variable model trained on $p(x)$ produces features $\mathbb E[h \mid x]$
usable for other tasks, so the same model serves both purposes.

## My take

The move described here is one of the most consequential in the book's whole argument, and it is easy to
read as a technical preference. It is not. It is the decision to replace **discrete structure search**
with **continuous parameter optimisation**, and it is the same move that appears everywhere in deep
learning.

Stated generally: whenever a design decision can be recast as a continuous parameter, gradient descent
will find a better answer than a search will, because the search cost is combinatorial and the gradient
cost is not. Attention is this move applied to which inputs a unit should read from — a discrete choice
turned into a continuous weighting. Neural architecture search's most successful variants relax the
discrete choice of operation into a weighted mixture for exactly the same reason. Mixture-of-experts
routing does it for which subnetwork handles an input.

Structure learning as described here is essentially dead in machine learning, though it remains alive in
causal discovery, where the graph *is* the object of interest rather than a means to a fit. That
distinction is worth keeping: if the structure is what you want to know, you must search for it; if it is
only a means to a good model, latent variables get you there more cheaply.

The dual use of latent variables — dependency modelling and representation — also explains why Chapters 13
through 16 are the same subject approached from different sides. A latent variable is a compressed
description of the input and an explanation of why the inputs correlate, and those are the same thing.
