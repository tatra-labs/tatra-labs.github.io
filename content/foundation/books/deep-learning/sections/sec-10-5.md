# 10.5 Deep Recurrent Networks

A recurrent network is already deep in one sense — unfolded, it is a chain of $\tau$ steps — but shallow
in another. This section asks what happens when depth is added *within* a step.

## Three transformations, all shallow

The computation of a standard RNN decomposes into three blocks of parameters: input to hidden state,
hidden state to hidden state, and hidden state to output. In the equations of 10.2 each is a single
affine transformation followed by a nonlinearity, which makes each one a shallow network.

The book cites experimental evidence that adding depth to these transformations helps, and gives three
ways to do it:

- **Decompose the hidden state into a hierarchy.** Stack recurrent layers, with the output of one
  recurrence feeding the next, so the lower levels transform raw input into a representation the higher
  levels operate on.
- **Add depth to each of the three transformations** — a multilayer network for the input-to-hidden,
  hidden-to-hidden, and hidden-to-output maps.
- **Add skip connections** alongside the extra depth.

## The cost

The third point is not decoration. Deepening the hidden-to-hidden transformation lengthens the shortest
path between a variable at step $t$ and one at step $t + 1$, and therefore lengthens every path across
time. Optimisation becomes harder for exactly the reasons Section 10.7 describes. The book's remedy is
skip connections, which restore a short path across the deepened block.

## My take

The trade-off named at the end is the entire content of the section and it generalises past recurrence: in
any deep architecture, adding depth is adding path length, and adding path length is making credit
assignment harder. Skip connections are the standard answer because they let depth be added without
lengthening the shortest path — a layer can be bypassed entirely if it has nothing to contribute.

Stacked recurrent layers became the default and remained so for as long as recurrent networks were used.
A two- to four-layer stacked LSTM was the standard architecture for translation and speech through the
mid-2010s, with residual connections between layers once the stacks got deep. Google's translation system
of 2016 was eight layers deep with residual connections between them, which is precisely the combination
this section recommends.

What is worth noticing is the asymmetry the section exposes. Depth *across* time is free in the sense that
it costs no extra parameters — that is the parameter sharing of 10.1 — and expensive in the sense that it
is where the gradient problems live. Depth *within* a step costs parameters and behaves like ordinary
feedforward depth. Recurrent networks made the first kind cheap and the second kind awkward, which is
close to the opposite of what a modern accelerator wants: a transformer has no depth across time at all
and stacks a great deal of depth within a position.
