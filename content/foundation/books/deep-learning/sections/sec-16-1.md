# 16.1 The Challenge of Unstructured Modeling

Chapter 16 begins by explaining why a joint distribution over many variables cannot simply be written
down, and the argument is a counting argument with four separate consequences.

## The cost

For $n$ discrete variables each taking $k$ values, a table of the joint distribution has $k^n$ entries.
For anything of realistic size this is not a large number, it is an impossible one — a modest colour image
of $32 \times 32$ pixels has 3072 values, and even reducing each to a single bit gives $2^{3072}$
configurations, vastly more than the number of atoms in the observable universe.

The book separates the consequences, because they are addressed by different techniques:

- **Memory.** Storing the parameters is impossible.
- **Statistical efficiency.** The number of examples needed to estimate a model grows with the number of
  parameters, so a model with astronomically many parameters cannot be fit from any dataset.
- **Runtime for inference.** Computing a marginal or a conditional requires summing over the table.
- **Runtime for sampling.** Drawing a sample requires reading the table.

## What structure buys

The escape is that most variables do not interact with most others directly. The book's illustration is a
relay race: the finishing time of the second runner depends on the first, and the third on the second,
but given the second runner's time the third is **conditionally independent** of the first. Modelling
only the direct interactions costs a number of parameters that grows with the number of *interactions*
rather than with the number of variables raised to a power.

The chapter's subject is the language for stating which interactions exist — graphs — and the algorithms
that exploit the resulting factorisation.

## My take

The four-way split is the useful part, because it shows that "intractable" means different things and the
fixes are not interchangeable. Memory and statistical efficiency are solved by *parameterisation* — a
neural network with a million parameters can define a distribution over $2^{3072}$ configurations because
it computes probabilities rather than storing them. Inference and sampling are not solved by that at all,
and Chapters 17 through 19 exist for them.

That distinction explains the shape of everything that follows. An autoregressive model gets all four for
free: parameters are shared, the factorisation is exact by the chain rule of 3.6, sampling is one
ancestral pass, and likelihood evaluation is one forward pass. An undirected model gets the first two and
fails at the last two, which is what makes it expensive. Reading Part III with this list in hand makes it
clear which problem each technique is attacking.

The counting argument is also the right response to a persistent confusion about generative models. A
model that assigns probabilities to $2^{3072}$ images has not memorised them and could not have; it has
found a compact rule that scores any configuration. Whether that rule captures the right structure is the
question, and it is a question about the parameterisation rather than about the size of the space.
