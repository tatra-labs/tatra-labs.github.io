# 10.12 Explicit Memory

Chapter 10 closes with the observation that a hidden state is a poor place to keep a fact, and with the
architectures proposed to fix it.

## The argument

Neural networks are good at storing **implicit** knowledge — the kind that is hard to articulate, such as
how to recognise a face. They are bad at storing explicit facts. The book puts the difficulty plainly:
back-propagation would need to present the same fact many times, and even then it is not stored reliably,
and a network cannot deliberately choose to remember something for later use.

The proposed remedy is a **memory network**: a set of memory cells external to the network, addressed by
a controller that learns to read and write. The controller is a neural network, and the memory is a
separate store it manipulates.

Addressing is the technical problem. Reading a single cell chosen by a hard index is not differentiable,
so these architectures read **many cells at once**, weighted by an attention distribution over addresses.
Writing works the same way, updating every cell in proportion to its weight. The **neural Turing machine**
adds the ability to learn where to read and write without supervision of the addresses, using
content-based addressing — comparing a query against the contents of each cell — as well as
location-based.

The book notes that memory cells are usually vectors rather than scalars, for two reasons: content-based
addressing needs enough dimensions for a comparison to be meaningful, and the cost of accessing a cell is
amortised over more information.

Finally, the authors observe that if the weighting is concentrated on one cell the mechanism is a genuine
read, and if it is diffuse the result is an average — and that the same attention mechanism can be used
between parts of a single network, so that one part chooses what to read from another.

## My take

That last sentence is the most consequential thing in the chapter, and it is a throwaway. Attention is
introduced here as an implementation detail — a way of making memory addressing differentiable — and the
observation that it can be used *within* a network rather than only against an external store is exactly
the transformer's premise, stated in one line and not pursued.

The architectures themselves went nowhere. Neural Turing machines and differentiable neural computers were
striking demonstrations, they solved algorithmic toy tasks, and nothing was ever deployed on them. They
are hard to train, the memory is slow, and the tasks they were good at turned out not to be the ones
anybody needed.

What is worth appreciating is how right the *diagnosis* was. Networks really are bad at storing explicit
facts in their weights, and every current approach to that problem is an external memory addressed by
learned retrieval — retrieval-augmented generation, vector databases, tool use, and the KV cache itself,
which is a growing store of past representations that attention reads from. The book identified the
problem, proposed the wrong solution, and named the right mechanism in passing.

Read as the closing note of Part II, this section is where the material points most clearly past itself.
The chapter spends fifty pages on how to keep a fixed-size state useful across time, and ends by
describing something that does not need one.
